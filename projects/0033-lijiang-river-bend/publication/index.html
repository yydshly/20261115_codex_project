场景、技术与写实目标

就按薄云下的漓江河湾做一个能在浏览器里漫游的 Demo 吧，用 Three.js + GLSL + 3DGS 纯代码生成，重点把山体、浅水卵石和水面倒影做得像实拍。

先让峰林、河床和水面共享同一地形，再从船上观察近处卵石、远处山影以及视角改变时的反射。

连贯的岸、水、空体验

继续，先把 4–6 分钟的完整航程串起来。从岸上登船，经过浅滩和岩壁，中途能接管木船，到宽湾靠岸后再飞起来，回看刚才经过的河段。

验收从干岸开始，经过登船、同船接管与恢复、靠泊、步行和空中回望。桌面与触屏视口跑完整航程，默认模拟时长约 4 分 31 秒。

高空视角暴露的远景边缘

那就先优化快飞时的远景吧，把远山和山雾衔接自然一点，别一飞高就看到那条直线，还是用纯代码生成。

加入后层山脊，让远山外缘沿同一视线收敛到天空色。139–279 米高程的同机位对照中，原有直线和矩形拐角消失。

Three.js JavaScript 场景库

提供场景、网格、相机和渲染入口。航程、驾驶与跟随规则由项目 JavaScript 更新，适用于可交互的三维漫游与展示。

GLSL GPU 着色语言

顶点着色器计算投影，片元着色器计算颜色与透明度。在这里控制岩石材质、浅水折射与倒影、薄云光照和远山雾色。

3DGS 程序化高斯渲染

由规则生成三维高斯，按视深排序，再通过 GLSL 投影为椭圆并透明合成。这里用它处理贴水薄雾与叶丛柔边。实景重建常从多视角影像优化高斯，本演示的山体、河床与载具由网格承载。

这次可以复用什么

生成规则将地貌、光照、浅水和操控串到同一坐标系。比如修改岩棚时，可以用同一份岸脚高程核对水线与船底净空，再以固定机位检查画面。换河段时可以沿用这种数据关系和验收方法。

当前验证基于 Chromium 桌面与触屏视口。高空朝上游俯看时，河道末端仍有一小段截边。长时真机性能与特定实景的测绘对齐仍待验证。
