03 / HOW EACH FILM WAS MADE

真正不同的是，怎样组织这条片。

下面对应本次源码和实际执行步骤，不把工具的一般宣传当作验证结果。

01 / REMOTION

先描述每一帧，
再复用网页组件。

  1. 用 React 的 Card 组件组织结果卡，SVG 描述网格和箭头。
  2. 读取当前帧，换算时间，再计算角度、得分和卡片位置。
  3. 增加第二个问题时，补上 13–19 秒的插值与文案分支。
  4. CLI 直接导出 H.264 MP4。
本例感受

结果卡和版式适合用组件复用。几何关系由代码自行计算，帧状态容易独立定位。

02 / MANIM

先建立图形对象，
再驱动对象变化。

  1. 用 Axes、Arrow、Arc 和原生文本建立图形。
  2. 用 ValueTracker 保存时间与查询角度，更新器连接数字、标签和得分。
  3. 把新增改稿拆成 13 秒原段、6 秒并行动画和 5 秒结尾。
  4. Python 场景直接渲染并编码 MP4。
本例感受

数学对象有现成表达。本次仍需手工处理卡片排版，并修正动态对象的缓存与字体设置。

03 / MOTION CANVAS

先布置节点，
再连接信号与时序。

  1. 用 Rect、Txt、Line 构成卡片、字幕和向量图。
  2. 得分与位置绑定角度信号，信号变化会传递到依赖节点。
  3. 用生成器顺序推进，再通过 all 同时更新角度与时间。
  4. 官方 Renderer 导出图片序列，再由 FFmpeg 编码 MP4。
本例感受

信号依赖让相关元素一起变化。导出流程多一步；节点布局和网页 DOM 的习惯不同。

WHAT THIS CASE ACTUALLY SHOWS

效果相近，制作方式有差别。

对这条成片，三种工具都能交付。Remotion 的优势在于帧状态与组件复用，Manim 提供数学图形对象，Motion Canvas 用信号与生成器组织相关动作。
选择额外工具的理由，是它的制作方式是否更适合你接下来反复做的作品。
