从 OpenStreetMap 开始

最初研究的是 OpenStreetMap 覆盖哪里、不同地区的道路、楼栋和店铺标得多细，以及这些开放数据能为可驾驶的城市场景提供哪些基础。

开放地图能提供什么

OpenStreetMap（OSM）是由全球贡献者共同维护的开放地理数据库。道路和步道可用于搭通行网络，建筑占地和岸线可用于定位环境，已收录的店铺和地标可用于标注。覆盖遍及全球，完整度和更新情况因地区和数据类型而异。

具体到一条街，要分别核对路网连通、楼栋轮廓和高度字段、店铺名称和点位。立面、招牌外观、路缘和坡度需要街景照片或测量资料补充。

实际下载到 F 盘的是 Overture Maps 的海上世界区域裁剪包。OSM 是研究入口，Overture 裁剪数据是原型实际使用的底图。

先搭出可信的空间环境，再让角色和车辆在其中活动。之前讨论的 GTA 风格指开放式驾驶、步行和街区活动。环境参照深圳蛇口，交互按本项目设计。故事和任务扩展放在环境验收之后。

从地图数据到可玩路线

按项目推进顺序整理。几条原型线并行存在，每条验证的问题不同。

  1. 选范围与数据

    从 OpenStreetMap 的全球地图覆盖出发，讨论 Overture、公开高程、照片和实景三维。以蛇口老街、海上世界、望海路比较道路、楼栋和店铺信息。海上世界有适合快速验证的道路、岸线、步道、骑行线和明华轮地标，小包先落在 F 盘。

    前期盘点用于挑选样板范围。三段各有可用信息，连续店招和街面高度仍待核实。

  2. 雨夜效果与交通试验

    先做广场南侧与明华轮的雨夜预览，逐步加驾驶、雨、灯光、路上车辆和行人。试玩暴露出画面偏暗、场景几何简化、行人和车辆接触失真以及穿模等问题。

    这些试验回答了操作是否连贯，也暴露了单靠效果和动作无法补齐环境的问题。

  3. 按平面和剖面搭灰盒

    把望海路同侧拆成 P 短停、B 骑行交会、E 入口。按底图中心线定位置，先画车、人、骑行动线，再用相对高差和通行净宽建立三维灰盒，放入样车验证落脚带、车门扫掠、坡道和入口连接。

    包内道路和步道有来源。停车布置、交会点、实体入口与大多数尺寸属于样板设计。

  4. 补近景资产和动作

    独立制作路面、路缘、灯具、排水、铺装、入口和临街构件。引入 CC0 路材、扫描街具、轿车和人物。给车轮与前门保留枢轴，分段处理靠车、开门、跨门槛、落座、下车和关门。随后加入骑行让行、步道行人避让、广场往返与签到。

    车型与人物为通用资产。动作和避让覆盖了样板中的有限情形。

  5. 搭城区骨架并接上近景

    扩大到蛇口邮轮母港、海上世界、水湾、蛇口老街、东角头和湾厦，形成约 6.7 × 5.6 公里骨架和单独的鸟瞰／街面漫游。另把老街到海上世界的可驾路线接到近景，使停车、下车、B 点让行、进广场成为连续操作。

    城区漫游按预设沿线观察。老街试玩支持手动驾驶，两者是独立程序。

  6. 拟合坡度并对照沿途照片

    用地表高程估算路坡。对照蛇口市场、嘉华小吃、荣村小区、蓝漪花园、玫瑰花园二期、望海路沿海步道、双玺、文化艺术中心和明华轮资料，做入口、招牌、窗与檐口、路口和滨水构件。

    修改改变了部分机位和地标辨识度。多数街段仍保留模板化的远近景。

  7. 核实整城复刻的素材缺口

    用户从实际驾驶视角继续看到重复的楼窗、树和底商。随后重新核查 F 盘数据、导出城区范围并查到深圳实景三维成果目录。蛇口的带纹理网格样片、交付方式和游戏使用许可仍待确认。

能怎么玩，验证到哪里

玩法有可执行的状态与碰撞规则。测试通过覆盖相应路径，街道尺度和实物仍需现场依据。

手动驾驶与停车步行

点进「蛇口老街 → 海上世界」画面，按 WASD 或方向键。空格刹车，E 上下车，可拖动镜头。默认从老街出发，也可从市场或望海路转角起步。时段有白天、黄昏、夜晚，天气有晴天、下雨。

沿指引线进 P 位停稳，在广场一侧下车。到 B 点等骑行者通过，沿坡道进入 E。在近景分支里另有步行往返、上车离开、签到等操作试验。

复盘与交接

最大的偏差是把玩法样板的推进和实景环境的达成混在了一起。原型跑通后，就该先核验整城实景数据和驾驶视角样片，再批量制作环境。

可以接着用的结果

  • 地理定位。现有范围、地标、路网、建筑轮廓和米制轴向可以作为导入与配准的参考。实际需要复核坐标及高程基准。
  • 玩法验收。保留按键、状态转换、车门净空、停靠、让行、路线衔接及可复跑的模拟检查。在新引擎中应按这些场景重新验证。
  • 通用素材。GLB 中的车辆、街具、局部材质和测试构件可用于临时制作。原始版本、许可、枢轴和纹理资料随资产保存。

需要重做的部分

  • 城市外观。大部分楼体、树、店面和小路依赖估算或模板。城区的主要视觉层需要实拍三维和街面素材覆盖。
  • 地面精度。以实际路宽、路缘与标高校验试玩可行面，把样板 P–B–E 的设计值与实景点位逐项对齐。
  • 可玩性覆盖。在全路网处理进出、坡面、碰撞、导航和交通。原型中的状态机、避让和碰撞规则需要随新环境重新接入与测试。

从数据到实景验收的顺序

  1. 确认数据范围和用途。首批沿用既有蛇口城区边界，查询带实拍纹理的 Mesh、地面高程、必要的地面照片或点云。核实格式、坐标、高程基准、采集日期、覆盖和本地游戏使用条件。
  2. 先验实景样片。用市场转角、望海路转角和海上世界入口的同机位实拍检查楼角、道路边界、路缘和能辨认的沿街细节。记录可测误差和照片缺口，确认地面视角后再铺开。
  3. 分块重建完整城区。以实景网格和地面资料为主，逐块配准、切片、核对建筑和街面。街道材料、树、标线和店面落到具体位置，按时间截面登记更新。
  4. 独立建立玩法表面。用与视觉一致的碰撞面、可走区域、车道、坡度和路口拓扑接回玩法。实景 Mesh 负责外观，游戏表面负责行驶、步行和物理反馈。
  5. 按整个范围验收。逐街核对地理位置与地面视角，抽查跨区和非主线驾驶，验证停车、上下车、行人及车流、晴天与雨夜的可读性。

场景入口打开现有版本。旧版保留推进过程和观察机位，当前手动试玩以「蛇口老街 → 海上世界」为准。3D 画面由浏览器 WebGL 渲染。

城区、布局和路线
  • 蛇口城区骨架六地标、车行及步行路由、建筑平面和城区覆盖。
  • 蛇口城区漫游白天、黄昏、夜景，鸟瞰、片区和预设街面路线。原画面标题为「蛇口全城」。
  • 蛇口老街 → 海上世界主试玩版本，支持市场和望海路起步、天气分离切换、P–B–E 交互。
  • 海上世界南侧平面布局数据依据、车人与骑行空间、断面设计和模型清单。
  • 停靠区三维灰盒空间和净空试验，标明 P 位、B 点和 E 入口。
望海路近景与交互样板
  • B 点骑行交会步行与骑行让行试验。
  • 广场入口雨夜雨效和近景灯光样板。
  • 广场入口资产样板铺面、雨夜材质、入口和扫描街具。
  • 雨夜街段近景前门与轮胎可动的样车、临街立面和街具细化。
  • 上下车试玩开门、人物跨步、落座、下车和座舱观察。
  • 广场接驳行驶至停靠区，接步行进入广场。
  • 广场往返停车、下车、进广场、返回并驶离。
  • 广场步道行人走动、局部互让与避开玩家的版本。
  • 雨夜签到玩家到达广场后按 F 签到，验证终点操作。
早期雨夜、车辆与街道活动
  • 海上世界雨夜早期场地与灯雨效果。
  • 雨夜驾驶早期自由驾驶、镜头和雨效。
  • 雨夜车流加入其他车辆与夜间亮度试验。
  • 街道活动早期人物、车流与人车避让。
  • 滨海巡游把滨海驾驶和沿途操作串成短程试玩。
  • 街道接触早期碰撞约束、人车接触与边界试验。
数据、模型与验收记录
  • 首批实景数据范围WGS84 范围，113.885°E 至 113.950°E、22.465°N 至 22.515°N。
  • 路线高程依据44 个记录位置，含坐标、原始 DSM、拟合高程与授权说明。
  • 本次自动验证记录市场接入、主路线场景、坡度、城区表面和漫游路径。
  • 城区量化汇总区域范围、原始数据数量、导出体块、路网、楼高与路径长度。
  • 广场入口环境资产 ZIP带纹理的 GLB、材质及街具来源，独立于试玩逻辑。
  • 近景环境与轿车 ZIP环境和轿车 GLB、保留来源与部件枢轴资料。
  • 海上世界原始小包约 1.74 MB。Overture 区域裁剪，压缩包是 GeoJSON 和索引。
  • 蛇口城区骨架 ZIP约 3.81 MB。含 GLB、数据索引、来源和说明。骨架 GLB 约 14.29 MB，含 0 张纹理。
