# 岩溶地表与垂直地下空间

本轮将峰林、石林、天坑、竖井、多层洞穴和地下河六站接入同一张3840×3120m地图，位于北部高平台。属于本库创作的教学样本，不是《红色沙漠》的地图或模型，也不模拟真实岩溶成因。

[进入六站主线](http://127.0.0.1:52932/expedition.html#karst-1) · [中央竖井](http://127.0.0.1:52932/expedition.html#karst-4) · [下层地下河](http://127.0.0.1:52932/expedition.html#karst-6)

## 沿主线看什么

| 场景 | 实际空间 | 对我们的参考和扩展价值 |
| --- | --- | --- |
| 峰林 | 9座高大峰体与平台低地，实体阻挡避让通路 | 先建立天际轮廓、峰间空隙与远近关系，再扩展山系与峡谷 |
| 石林 | 67根细柱岩体，顶底侧面与条带表面，柱间可走 | 比较大峰与近人岩柱的尺度；按通路组织疏密，而非堆满素材 |
| 天坑 | 坑缘74m、盆底约6m，中心继续向竖井打开 | 地表凹陷形成开放空间，观察视线、坑壁与入口栈道的关系 |
| 竖井 | 井底−34m，实际井壁、透空升降台、缆线与层间栈道 | 从二维地形高度场扩展为垂直连接；避免全图海面错误穿过井筒 |
| 多层洞穴 | 上层约38m干廊回环，下层约−28m并继续下降，各有地板、洞顶和洞壁 | 同一平面坐标可以有多层空间；查询与通行必须携带当前高度 |
| 地下河 | 下层干岸、实际深槽，水面−35m至−35.6m、中心约3m深 | 水位和床底与当前洞层共用数据；以后可加支流、补给、湿岸生态 |

## 操作与观看

1. 从六站入口开始构建主线，每站按岩体骨架、地表洞壁、地下水域和完整立体空间四层讲解。
2. 第四站到第五站会乘平台从74m降到38m，绕上层洞廊返回，再降到−28m，沿下层干路前进。中央升降段安排32秒，转场镜头明确标记为教学镜头。
3. 升降时可以拖动转向，暂停会同时保留平台与乘客位置；步行暂时锁定。减少动态不会取消必要交通，只停止河面示意流线。
4. 自由漫游时，沿原栈道回到中央平台后选择地表、上层或下层。上层桥从平台东侧出发，下层桥朝东南连接下层洞道；不要从边缘尝试坠落。
5. “岩溶垂直剖视”移开上方覆盖与洞顶侧壁；上层/下层按钮保留所选地板，另一层用轮廓线提示。观察相机与小地图都来自同一套几何。

## 构建规则与边界

- 地表峰体和天坑采用地形高度场与程序化岩体；地下使用分层空腔网格。相交的同层廊道平滑合并，独立的上下层不会被合成最低地面。
- 中央井筒从洞层地板与洞顶网格中留空，海面也在同处留出开口。平台的实际位置控制物理支撑，小地图模型不会改变它。
- 地下河与岸路分开，深槽限制步行；教学补光帮助观察空间，开放井筒保留外部光照与天气。
- 六站对应第77至82站；当前总计82站328处观察，原76站304个观察标识与浏览器存储键保留。水系、植被与地形专线数量不变。
- 形体、地层条带、海拔和地下水位均为创作参数。当前没有侵蚀、地下补给、水量循环、塌陷、自由坠落、洞穴生态或真实升降机动力学。
- 按用户选择，浏览器实景/GPU验收暂缓，只提供内置浏览器入口；没有新增实景截图。CPU检查只能证明几何、通路与控制状态，不能证明最终画质。

## 验证入口

运行 `node scripts/check-karst.mjs`，报告见 [assets/karst-check.json](assets/karst-check.json)。检查原路线/观察标识保留、实际步行、上下层隔离、升降同步与暂停、竖井海面开口、洞顶和洞壁遮挡、剖视恢复、减少动态和三种视口的相机范围。
