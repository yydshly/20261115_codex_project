# 验证记录

2026-11-16，Windows，Python 3.10.11，NumPy 2.2.6，OpenCV 4.13.0.92，Pillow 11.3.0，ONNX Runtime 1.23.2，Blender 5.2.2 LTS，RTX 4070 Laptop / OptiX。

## 实际执行

1. 用此前参考视频前 6 秒制作新的 600×720 竖幅输入文件，并沿用该文件自带声音。使用同一原人物，未伪称已经测试其他身份。
2. 通过 `init` 建立全新任务，默认人物裁切设为 `null`；将帧率改为 30，标题改为“换一段素材 / 继续讲故事”，更换正文、关键词、收尾文案与蓝绿色配色。
3. 执行完整 `run`：180 帧人物抠像，无面积启发式异常；自动生成 77 帧同步屏幕贴图和三维渲染；导出 6 秒、1280×720、30 fps 的完整成片。完整解码、帧数、音轨时长检查通过；原声音轨相关性 0.999889，偏移 0 个 8 kHz 采样点。观察分镜确认人物、文字、场景和回归镜头实际存在。
4. 只修改标题为“换文案后 / 复用同一流程”，重新运行：日志确认复用抠像与三维缓存；得到独立的新成片目录。再次完成全解码及音画验证，分镜确认标题已改变，其他图像素材继续复用。
5. 检查 SRT 导入：`营收 123.45 万元，增长 12.5%。` 与多行字幕文本、毫秒时间原样保留。该句仅用于解析检查，没有假冒成参考人物实际说的话。
6. 反例检查：重叠字幕、无法放入版式的超长标题均被拒绝；对已有任务再次 `init` 被拒绝，原配置 SHA-256 保持一致。
7. 使用 `skill-creator/scripts/quick_validate.py` 检查技能元数据与未完成占位内容。

第一次执行包含模型推理与 GPU 渲染；只换文案的第二次执行不重新推理或渲染。耗时取决于硬件、片长和采样数，不能把本机结果视为其他设备的速度保证。

## 验证范围

验证了更换输入文件、输入比例、片长、帧率、文案、字幕版式与场景配色，以及缓存复用。未验证其他身份、多人、严重遮挡、长达 180 秒的成片或每一种 CUDA/CPU 环境。轮廓面积检测不证明抠像绝对正确；头发边缘与字幕阅读节奏仍需看视频。

此前 10 秒小样仅是风格参考，后续运行不读取其原始脚本或场景文件。三维布景由本技能的 `scripts/scene.py` 从零创建；RVM 权重和 Blender 是外部运行依赖。
