# 单张运河参考图：VGGT → Blender 实验

日期：2026-11-15。目标是实际检查：在旧版运河场景上增加单图预测深度，是否能改善空间布局。

## 实测结论

**单图推理、参数拟合、普通网格修改与 Blender 渲染均已跑通，但本轮 B 没有比旧版 A 更贴近原参考图。** 这不是 VGGT 的通用性能结论，而是该概念图、该语义模型与该拟合方法的结果。

![实际 Blender A/B 对照：左旧版 V4，右 VGGT 深度辅助的几何校正](../../assets/canal-single-vggt/comparison.png)

[原参考图](../../assets/canal-single-vggt/reference.png) · [A 原尺寸](../../assets/canal-single-vggt/A-old-v4.png) · [B 原尺寸](../../assets/canal-single-vggt/B-vggt-guided.png) · [B 侧视](../../assets/canal-single-vggt/B-side.png)

| 检查 | 实际结果 |
| --- | --- |
| 官方权重 SHA256 | 与预期完全一致 |
| 推理 | CPU BF16，588.10 秒；含模型加载和结果保存合计 598.14 秒，不含下载和环境安装 |
| 深度与镜头 | 输出 518×294 深度，fx=469.73、fy=473.90 px；深度任意尺度 |
| 12 个拟合锚点 RMS | A：36.92 px；B 解析投影：54.46 px，实际 Blender 投影：54.39 px；评价尺寸 1672×942，数值越低越贴近这些锚点 |
| 边界信号 | 高度缩放达到下限 0.55；说明该有界模型的拟合存在明显约束冲突 |
| B 主视角 / 侧视渲染 | 27.98 / 29.58 秒，各 2109 个对象、2015 个网格对象 |
| 实际工程重开 | Blender 成功读取；保留主相机，无外部图像贴图依赖 |
| 历史工程保护 | V3/V4 前后 SHA256 相同 |

A 原先按图像锚点拟合，B 本轮按预测三维点拟合，优化目标不同，不能把这组 RMS 当成公平的算法能力排名。它说明的是：**此次把预测深度作为主要约束，没有改善既有场景的图像对齐。** B 还同时改变了相机、建筑和河道，无法把变化归因于某个单独变量。旧锚点本身为近似标注，也可能采到轮廓边界的其他表面。

实际观察：立面与岸边有较清晰的深度结构；天空、水面和桥洞的置信分数偏低。B 的建筑比例、镜头裁切和桥位出现偏移，旧版缺少的湿润材质、植物和复杂背景也没有被深度自动补上。全局比例与布局变形只是有限表达能力，不能据此判断任意语义重建方法都会失败。

![单图深度表面从稍偏侧面渲染，显示天空和水面处的断裂及展开](../../assets/canal-single-vggt/depth-surface-side.png)

上图是 **2.5D 诊断网格**：38,073 顶点、69,774 三角形，参考图投影颜色，只有可见表面；不是完整建筑或新视角真值。脚本主动断开了局部深度比大于 1.12 的连接，所以部分破洞是显示策略，而非 VGGT 输出了缺失像素。另见 [深度伪彩图](../../assets/canal-single-vggt/depth-color.png)（近蓝远红、对数 2–98 百分位截断）与 [相对置信图](../../assets/canal-single-vggt/confidence.png)（更亮表示模型分数更高）。

**对后续的价值判断：** 本例适合把深度作为软参考、辅助分层和初步布局，不适合直接当硬尺寸标尺。若目标是更像这张概念图的可编辑场景，优先改进同相机构图、语义部件、材质与布景，并在不可靠区域保留人工/结构先验。若目标是可信的真实空间，下一轮应采集实际多位置照片和独立实测长度，验证多视角一致性。单张图没有恢复真实尺度或背面信息。

## 变差原因复核：拟合设计是明确的混杂因素

用户追问后，同日回查了旧版与新版代码，并在**冻结原 VGGT 输出**的条件下做参数对照，没有重跑模型、没有新增渲染，也没有覆盖首轮 B。

| 条件 | 同一组近似拟合锚点 RMS（px） |
| --- | --- |
| 重算旧版 V4 投影 | 36.92 |
| 保留旧模型及机位，只换成预测内参 | 103.58 |
| 首轮 B：固定预测内参，以三维点残差为主 | 54.46 |
| 保留 B 的预测内参、参数化方式和边界，仅优化图像重投影 | 17.80 |

最后一行只是在相同参数表达能力下更换目标函数的诊断结果；不是新完成的 Blender 版本，不是独立验证。相比旧版 V4，它还多了形状变量且没有旧版岸线项，不能把 17.80 与 36.92 当作改进幅度的公平排名。

可确认的问题：

- 旧版同时保留图像锚点和岸线约束；首轮 B 换成三维点残差为主，没有显式图像重投影和岸线项，因而允许以构图偏移换取更贴合预测点。17.80 的诊断解说明，同一预测焦距并没有把图像误差必然限制在 54.46。
- 预测焦距被固定。水平等效焦距从旧版约 27.00mm 换到约 32.65mm；直接替换就造成明显构图变化。两者均未用真实相机标定，不能据此判定哪个才是真焦距。
- 仅 12 个人工近似锚点，每点取 3×3 深度中位数；部分在屋檐、桥洞等轮廓边缘，图像位置与语义模型三维点未必严格对应。
- 置信分数只用于相对降权，设置了最低权重，没有剔除低分轮廓点；建筑、河道、桥与机位又可联合变化，形状先验较弱，出现高度缩放触下限的解。
- 相机转换实现基本一致：解析投影 RMS 54.46、实际 Blender 投影 RMS 54.39，相差约 0.07px。这一检查未发现足以解释构图偏移的坐标转换错误。

结论应表述为：**本轮明确暴露了深度接入和优化目标设计的问题；单图预测不确定性可能放大问题，但尚无真实深度或多图对照来量化两者贡献。** 首轮结果不能证明单图 VGGT 没有价值，更不能证明加预测深度必然改善几何。

下一轮若继续，应保持旧版图像/岸线约束与结构先验，仅逐步加入可靠区域的软深度约束，并把“只加预测内参”“再加深度”“再放开形状”分开检查；预测内参也应允许校正。需要独立检查点或真实多视角数据，避免只用参与拟合的锚点评价。

复核脚本：[audit_fit.py](audit_fit.py)；数据：[fit-audit.json](reports/fit-audit.json)。

## 对照设计

- 输入：历史运河实验的同一张 1672×941 参考图；SHA256 `6ebfd8652e498e31ad522045a22e7abdb32b92f5b5e825f62ae7df13ec844f1e`。
- A：历史 V4 场景，本轮以 Cycles CPU、32 samples、1000×563 重渲染。
- B：以历史 V3 的语义模型为起点，用 VGGT 估计的内参与深度拟合相机、桥位、河道及建筑比例，然后实际修改 Blender 网格并渲染。材质、世界光照及灯光强度沿用旧版；灯的位置随几何变换。相机和场景比例都会改变。
- 12 个图像锚点沿用旧实验的人工作近似标注；它们同时参与拟合，因此锚点误差只能说明拟合一致性，不能视为独立的重建精度。
- 侧视图只用于检查几何与遮挡，没有对应真实侧视照片，不能证明隐藏面的正确性。

这是有语义模型起点的最小对照实验，不是从空场景自动识别全部物体，也不是完整复现作者的多照片工作流。单张 AI 概念图没有已知真实相机、尺度和测量深度。

## 实际运行方式

- 官方 [VGGT 源码](https://github.com/facebookresearch/vggt/tree/a288dd0f14786c93483e45524328726ab7b1b4ce)，提交 `a288dd0f14786c93483e45524328726ab7b1b4ce`。
- 官方 [facebook/VGGT-1B 权重](https://huggingface.co/facebook/VGGT-1B)，`model.safetensors`，5,026,367,224 bytes，SHA256 `f164acf60724910d8fe1578bb499d800850c7bb0948db7555c413f9fbe60467e`，已核验。
- Windows，Python 3.10.11，PyTorch 2.3.1+cpu，NumPy 1.26.4；Blender 4.5.9。
- 启用 camera/depth head，关闭本实验不使用的 point/track head。按官方预处理得到 518×294 输入，保留完整画面，尺寸取 14 的倍数。
- 初次 Float32 文件映射受内存限制失败；实际改为流式读取并转换为 BF16，在 CPU autocast 下运行，位姿解码用 Float32。未改变学习参数来源，但不等同于官方 GPU 数值精度基准。
- 推理的深度尺度任意；模型置信分数不是校准后的正确率。

依赖、第三方源码及大权重位于独立本地运行目录，不纳入研究仓库。权重许可应以官方模型卡为准，不能因源码许可而假定权重允许所有用途。

## 脚本

1. `download_weights.py`：下载及校验官方权重。并发下载若被中断，预分配文件可能是完整长度但内容未齐；必须通过 SHA256，不能只检查文件大小。
2. `infer.py --source <官方源码目录> --weights <model.safetensors> --image <原图> --out <结果目录>`：保存深度、内参、置信图及报告。
3. `fit_layout.py --prediction <结果目录/prediction.npz> --old-alignment <历史 alignment-v4.json> --out <结果目录/layout-fit.json>`：使用置信权重做有界稳健拟合；11 个变量包括任意深度尺度与场景比例，解并不唯一。
4. Blender 执行 `render_trial.py -- --old-root <历史项目> --out <结果目录> --stage baseline` 生成 A；再加 `--fit <layout-fit.json> --stage guided` 生成 B、可编辑 `.blend` 和投影一致性报告。
5. Blender 执行 `depth_surface.py -- --prediction <prediction.npz> --out <结果目录>`，仅生成可见表面的 2.5D 诊断网格；其参考图颜色来自投影贴图，不能作为完整重建的证据。
6. `make_board.py --results <结果目录> --out <对照图片路径>` 生成实际 A/B 图。

运行 Blender 时在 `--python` 之前加 `--background --factory-startup --python-exit-code 1`，脚本参数放在 `--` 之后。原历史 `.blend` 只读，实验另存新文件；渲染脚本核对前后哈希。
